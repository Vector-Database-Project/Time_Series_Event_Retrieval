Data Processing Pipeline

The current ECG preprocessing stage converts raw MIT-BIH records into fixed event windows, derives the frequency view from the saved time-domain windows, saves the processed dataset to processed/v1, and then builds a derived train/test split at processed/v1tts.

Pre-samples 180
Post-samples 180
Chunk length 361 samples
Sampling rate 360 Hz
FFT bins stored 181
Test Train Split policy Label-stratified random

Implemented flow

  • parse and filter annotations
  • extract fixed beat-centered time-domain windows
  • mean-center each channel per window and compute one-sided FFT
  • save TD, FD, labels, label map, and frequency bins under
  • split the full processed dataset into test and train sets

Chunking policy

Beats are extracted using a fixed beat-centered symmetric window. With pre_samples = 180, post_samples = 180, and a sampling rate of 360 Hz, each event window contains 361 samples, which corresponds to approximately 1.003 s of signal. This keeps every extracted event on a common length and preserves aligned local waveform context for downstream embedding and retrieval.

Frequency-domain preprocessing note

The saved time-domain representation keeps the raw extracted ECG window unchanged. The frequency-domain representation is derived from that same saved window after per-channel mean-centering, followed by a one-sided FFT. This reduces the dominance of the DC component while preserving a consistent spectral view across windows. With N = 361 and fs = 360 Hz, the one-sided FFT stores 181 bins with a frequency resolution of approximately 0.997 Hz/bin.
