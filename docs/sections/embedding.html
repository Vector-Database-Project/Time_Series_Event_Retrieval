Embedding Architectures and Evaluation Pipeline

After preprocessing, the saved train and test splits are passed through a unified embedding runner. Every run uses the same benchmark inputs and the same retrieval evaluator. The only controlled changes are the input representation, the embedding method, and the embedding dimension.

Representation design

  • Time: flattened beat-centered waveform windows
  • Frequency: flattened FFT magnitude-phase representation from the same events
  • Mixed: direct concatenation of the aligned time and frequency feature blocks

Execution policy

A single runner executes the full 3 × 3 × 2 matrix. This keeps the experiment symmetric: all methods read the same train and test roots, use the same class mapping, follow the same naming convention, and write outputs to parallel folders under results/embeddings/ecg_v2.

Retrieval evaluator

The evaluator uses train embeddings as the reference pool and test embeddings as queries. For each test query, it retrieves the top-K nearest train embeddings under L2 distance with K ∈ {1, 5, 10}. The predicted class is assigned by majority vote over the retrieved labels.

  • metrics reported: accuracy, macro precision, macro recall, and macro F1
  • artifacts saved: metrics JSON, predictions, top-K neighbors, and confusion matrices
  • all runs are evaluated with the same retrieval policy to keep comparisons directly interpretable
