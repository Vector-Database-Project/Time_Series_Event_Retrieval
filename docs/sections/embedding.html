Embedding Methods and Retrieval Evaluation

Embedding methods 3
Input representations time, frequency, mixed
Embedding dimensions 64, 128
Experimental matrix 18 runs

Following benchmark construction, each ECG beat event is mapped into a lower-dimensional feature space and evaluated through nearest-neighbor retrieval. The experimental design varies three factors, embedding method, input representation, and embedding dimension, while holding the benchmark split and downstream retrieval protocol fixed. This structure allows differences in retrieval behavior to be interpreted as differences in representation and embedding performance under a common evaluation setting.

Compared Methods and Input Representations

Method Method class Conceptual role in the benchmark
Gaussian Random Projection Linear baseline Projects each input into a lower-dimensional random subspace, providing a simple non-learning baseline for testing whether class structure is already recoverable after preprocessing.
UMAP Unsupervised manifold embedding Learns a low-dimensional representation by preserving neighborhood structure in the training data, allowing retrieval quality to reflect geometry induced without label guidance.
Supervised UMAP Label-aware manifold embedding Incorporates class information during fitting so that events from the same class are encouraged to occupy more coherent neighborhoods in the learned space.

Gaussian Random Projection serves as a useful baseline because it does not attempt to learn task-specific geometry. If retrieval quality remains competitive under random projection, this suggests that the preprocessing and input representation already expose substantial class structure. UMAP and Supervised UMAP instead learn lower-dimensional manifolds from the training data, with the latter introducing label information to encourage stronger within-class grouping.

Three input representations are compared. The time representation consists of flattened beat-centered waveform windows. The frequency representation is derived from the same events in the Fourier domain using aligned magnitude-phase features. The mixed representation is formed by direct concatenation of the aligned time and frequency feature blocks. For each method, embeddings are produced at dimensions 64 and 128, yielding a full 3 × 3 × 2 comparison matrix.

Retrieval Protocol and Metrics

Retrieval is performed in the learned embedding space using the train split as the reference pool and the test split as the query set. For each test embedding, nearest neighbors are identified from the train embeddings under Euclidean distance, d(q, x) = ||q - x||2. The evaluation reports results at K = 1, 5, 10. For each query, the predicted class is determined by majority vote among the labels of the top-K retrieved neighbors.

This protocol evaluates whether the learned embedding places clinically similar beat events in local neighborhoods. A strong result therefore indicates not only separability in the global feature space, but also local consistency in the class structure recovered by nearest-neighbor search.

Metric Definition Interpretation in this benchmark
Accuracy (number of correct predictions) / (total number of queries) Measures overall retrieval-based classification correctness across the test set.
Precision TP / (TP + FP) Measures how reliable the predicted class assignments are when a class is selected.
Recall TP / (TP + FN) Measures how well the retrieval process recovers queries belonging to each class.
F1 score 2PR / (P + R) Balances precision and recall, making it useful when both false positives and false negatives matter.
Macro averaging (1 / C) Σ metricc over classes Weights all classes equally, preventing majority classes from dominating the reported summary.
In this benchmark, macro precision, macro recall, and macro F1 are especially informative because they emphasize class-balanced retrieval behavior rather than performance dominated by the most frequent class alone.

Together, this evaluation design provides a controlled basis for comparing whether retrieval quality is driven more strongly by the form of the input representation or by the embedding family used to organize the resulting event space.
